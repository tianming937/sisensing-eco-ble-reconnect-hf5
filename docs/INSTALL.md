# 安装与使用说明

本文分为“取得 APK”“选择安装路径”“完成系统设置”“验证自动重连”和“故障回退”五部分。请完整阅读后再操作。

## 1. 安装前准备

你需要：

- 一部支持 BLE 的 Android 手机；
- 当前有效且尚在使用期内的硅基轻享探头；
- 一份由可信来源构建、且签名身份已知的 v16.1-hf5 APK；
- 可靠的备用血糖测量方式；
- 如需使用命令行，准备 Android Platform Tools（ADB）。

安装前记录：

- 当前 App 版本、包名和签名证书指纹；
- 当前账号和探头绑定状态；
- 是否有未同步的重要本地数据；
- 现有 APK 是否还能取得，以便回退。

不要在没有备用测量方案时进行升级或故障复现。

## 2. 验证 APK

先计算 SHA-256：

```powershell
Get-FileHash -Algorithm SHA256 "D:\Downloads\sisensing-v16.1-hf5-signed.apk"
```

再验证签名和版本：

```powershell
$env:JAVA_HOME = "C:\Program Files\Java\jdk-17"
& "D:\Android\Sdk\build-tools\36.0.0\apksigner.bat" verify --verbose --print-certs "D:\Downloads\sisensing-v16.1-hf5-signed.apk"
& "D:\Android\Sdk\build-tools\36.0.0\aapt.exe" dump badging "D:\Downloads\sisensing-v16.1-hf5-signed.apk"
```

预期版本字段：

```text
package     = com.sisensing.eco
versionCode = 37
versionName = 02.23.01.00-v16.1-hf5
minSdk      = 21
targetSdk   = 34
```

本项目历史真机测试制品的 SHA-256 为：

```text
C70316F72234908FD722FDC63A5FBB406A13F4B95D53A6296270831A1464DDA2
```

测试签名证书 SHA-256 为：

```text
efc23cb150fac98a6b45d93fc0914794b778e542fed6ff7c21925eab824dba8c
```

仓库不提供该 APK 或私钥。自行构建的 APK 哈希和签名证书通常不同，这是正常现象。

## 3. 选择正确的安装路径

### 路径 A：覆盖安装（保留 App 本地数据）

只有同时满足以下条件才能覆盖：

1. 包名都是 `com.sisensing.eco`；
2. 新旧 APK 使用完全相同的签名证书；
3. 新 APK 的 `versionCode` 不低于当前安装版本；
4. 现有数据结构与升级路径兼容。

通过 ADB 查询当前版本：

```powershell
adb shell dumpsys package com.sisensing.eco | Select-String "versionCode|versionName|firstInstallTime|lastUpdateTime"
```

执行覆盖：

```powershell
adb install -r "D:\Downloads\sisensing-v16.1-hf5-signed.apk"
```

预期返回：

```text
Success
```

`INSTALL_FAILED_UPDATE_INCOMPATIBLE` 表示签名不一致；`INSTALL_FAILED_VERSION_DOWNGRADE` 表示版本码更低。不要绕过这些保护。

覆盖完成后再次查询版本，并确认 `firstInstallTime` 保持不变。覆盖安装通常保留数据，但不能替代备份，也不能保证跨任意历史版本的数据迁移安全。

### 路径 B：卸载旧版后全新安装

签名不一致时，Android 不允许覆盖。卸载会清除该 App 的本地账号状态、数据库、设置和探头会话数据；进行前必须确认：

- 重要数据已经同步或备份；
- 你知道账号重新登录方式；
- 你了解当前探头是否允许重新绑定；
- 备用测量方案已经可用。

然后才执行：

```powershell
adb uninstall com.sisensing.eco
adb install "D:\Downloads\sisensing-v16.1-hf5-signed.apk"
```

从文件管理器安装时也遵循同一签名规则。不要因为系统提示“无法安装”就直接卸载，先确定失败原因。

### v14/v15/v16 系列的特别说明

- v16.1-hf5 的测试签名可覆盖使用同一证书签名的本项目 v14/v15/v16/hf1-hf4，前提是版本码允许。
- 官方硅基轻享与本项目修改版签名不同，双方不能互相覆盖。
- 某台手机能覆盖、另一台不能，常见差异是原安装包签名、版本码或历史数据库状态不同，而不是手机型号本身。
- 曾观察到旧版数据环境下覆盖后连接/算法路径异常、全新安装却正常；hf5 修复了已知算法差异，但无法承诺任何未知旧数据都可无损迁移。

## 4. 首次启动和权限

安装后：

1. 启动硅基轻享，确认短信登录和密码登录界面可正常使用。
2. 授予“附近的设备”或蓝牙扫描/连接权限。
3. 允许通知，以便前台服务稳定运行。
4. Android 12 以下如系统要求，授予定位权限；某些系统把 BLE 扫描与定位权限绑定。
5. 登录并确认当前探头信息正确。
6. 等待主界面出现持续更新的数据，不要只看“已连接”文字。

三星 One UI 建议设置：

1. `设置 → 应用 → 硅基轻享 → 电池 → 不受限制`；
2. `设置 → 电池 → 后台使用限制 → 从不自动休眠的应用`，加入硅基轻享；
3. 允许通知和附近设备权限；
4. 不要同时让第二部手机连接同一探头。

## 5. 验证亮屏和灭屏自动重连

先做低风险短时测试，再做中长时间测试。不要用关闭蓝牙、清数据或杀进程的方式制造故障。

### 5.1 短时亮屏测试

1. 确认数据正在更新；
2. 携带探头离开手机至超出蓝牙范围；
3. 等待确认断连；
4. 返回手机附近；
5. 记录从返回范围到恢复新数据的耗时。

### 5.2 灭屏测试

1. 确认数据正在更新后锁屏；
2. 携带探头自然离开范围；
3. 保持手机灭屏，等待 10～30 分钟后返回；
4. 返回后不要亮屏、解锁或打开 App；
5. 继续等待 2～5 分钟；
6. 最后亮屏检查：亮屏前是否已经恢复新数据，而不是亮屏后才开始转圈。

如可使用 ADB，同时观察：

```powershell
adb logcat -v threadtime -s SiSensingBLEv16:I SiSensingAlgoHF5:E AndroidRuntime:E
```

灭屏重连的关键证据包括：

- `FILTERED_SCAN_SCREEN_OFF_MULTI_HF4`；
- 屏幕仍为关闭状态时出现扫描结果或 GATT 连接；
- 服务发现、认证和有效数据在亮屏前恢复；
- 没有 `FATAL EXCEPTION`、`SIGABRT` 或 ANR。

只看到亮屏后数秒连接成功，不能证明灭屏已自动重连。

### 5.3 中长时间测试

短时测试稳定后，再测试 2～4 小时离开。记录：

- 断连时刻和屏幕状态；
- 返回蓝牙范围的时刻；
- 首次重试和首次发现探头的时刻；
- GATT 成功、服务发现和首个新数据的时刻；
- RSSI；
- 是否曾打开 App 或点“连接”。

建议至少观察一个完整夜间周期和一次探头更换。

## 6. 常见问题

### 一直转圈但连接不上

按顺序检查：

1. 探头是否还在寿命内并仍在广播；
2. 同一探头是否正在被另一部手机占用；
3. 手机与探头是否在同一身体侧，RSSI 是否过低；
4. 蓝牙和附近设备权限是否被撤回；
5. 前台服务是否运行；
6. 日志是否持续出现 `status=133/147` 或扫描 0 结果；
7. 当前探头算法是否为已支持四种之一。

不要通过高频点击“连接”叠加更多请求。

### 新探头后不读数

查看 `SiSensingAlgoHF5`。如果出现 `ALGORITHM_UNSUPPORTED_OR_VERIFY_FAILED`，说明新探头算法未知或预检失败。hf5 会故意拒绝计算；请提交脱敏后的算法标识和错误类型，等待明确适配，不能把未知算法强制映射到旧算法。

### 覆盖安装后异常，全新安装正常

这通常指向旧数据、旧任务数据库、旧绑定信息或跨版本迁移差异。先保存脱敏日志并确认备用监测，再决定是否全新安装。不要在没有备份时直接清数据。

### 信号很弱

`-90 dBm` 以下已属很弱，`-100 dBm` 左右容易产生反复断连。把手机放在探头同侧、减少身体遮挡、远离强干扰源。更激进的软件扫描无法补偿物理信号缺失，反而可能增加耗电和蓝牙栈压力。

## 7. 回退

回退也必须满足签名和版本码规则。低版本覆盖通常需要 `-d`，但即使安装器允许，旧代码也可能无法读取新版本已经迁移的数据：

```powershell
adb install -r -d "D:\Backup\previous-same-signer.apk"
```

建议把回退视为需要单独验证的操作，而不是无条件安全。回到官方版通常必须卸载修改版，会清除本地数据。

## 8. 紧急情况

App 无数据、读数异常、症状与读数不一致时，立即使用指尖血糖仪或其他可靠方式复核。如果出现严重低血糖/高血糖症状、意识异常、抽搐、昏厥、持续呕吐或呼吸困难，请按既定急救方案处理并联系急救或医生，不要等待蓝牙恢复。
